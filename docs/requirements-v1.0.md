# 어른이농구 리그별 스코어 APP 요구사항·설계서 v1.0 확정본

## 1. 프로젝트 목적

농구 동호회의 분기별 리그 운영 데이터를 기존 Excel 대신 웹/PWA 기반 앱으로 관리합니다.

주요 관리 대상은 다음과 같습니다.

- 분기별 팀 편성
- 경기 일정 및 경기 결과
- 팀 순위
- 팀 연승 기록
- 회원 출석
- 회원별 실제 출전팀
- 분기별 및 전체 출석률
- 과거 리그 기록 조회

초기 버전에서는 경기별 개인 득점만 관리하며, 리바운드와 어시스트 등의 추가 개인 경기 스탯은 관리하지 않습니다.

# 2. 기본 운영 규칙

## 2.1 분기 리그

리그는 분기 단위로 운영합니다.

예:

- 2026년 1분기
- 2026년 2분기
- 2026년 3분기
- 2026년 4분기

분기가 변경되면 팀 편성을 새로 진행합니다.

동일 회원이라도 분기마다 다른 팀에 소속될 수 있습니다.

예:

김철수

- 2026년 2분기: 컬러
- 2026년 3분기: 블랙
- 2026년 4분기: 화이트

과거 분기의 팀 편성, 경기 결과, 순위, 출석 기록은 삭제하지 않고 계속 조회할 수 있어야 합니다.

## 2.2 리그 우승팀

리그 종료 후 관리자는 해당 리그의 최종 우승팀을 확정합니다.

- 우승팀은 순위 1위를 매번 동적으로 표시하지 않고 관리자가 확정한 결과를 저장합니다.
- `League`의 `winner_team_id`가 해당 리그의 최종 우승팀인 `Team`을 참조합니다.
- Backend는 `winner_team_id`가 해당 `League`에 소속된 `Team`인지 반드시 검증합니다.
- 공개 사용자는 최종 우승팀과 당시 우승팀 멤버를 조회할 수 있습니다.
- 우승팀 멤버는 해당 리그의 `LeagueMember` 팀 편성을 기준으로 조회합니다.

# 3. 회원

## 3.0 접근 권한과 회원 구분

시스템 접근 권한은 비로그인 일반 사용자와 관리자 두 종류입니다. 정회원과 게스트는 인증 Role이 아니라 `Member`의 회원 구분입니다.

## 3.1 회원 정보

회원은 다음 정보를 가집니다.

- 회원 ID
- 이름
- 태어난 년도
- 키
- 포지션
- 회원등급
- 활성 여부
- 관리자 비고

포지션은 2개 이상 입력할 수 있습니다.

기본 포지션 값은 다음과 같습니다.

- PG
- SG
- SF
- PF
- C

키는 cm 단위의 정수값으로 관리합니다.

회원등급은 두 종류만 존재합니다.

- 정회원
- 게스트

탈퇴한 회원은 삭제하지 않고 비활성 처리합니다.

과거 경기 및 출석 기록 보존을 위해 이미 기록이 존재하는 회원을 물리적으로 삭제하지 않는 것을 기본 원칙으로 합니다.

## 3.2 관리자 비고

회원별로 관리자가 자유롭게 작성할 수 있는 `비고(note)` 필드를 제공합니다.

예:

- 신규 가입
- 장기 출장 예정
- 회비 관련 메모
- 기타 운영상 특이사항

비고는 관리자 전용 정보입니다.

따라서 다음 원칙을 적용합니다.

- 일반 사용자 화면에는 표시하지 않습니다.
- 공개 회원 조회 API에는 포함하지 않습니다.
- 관리자 전용 회원 조회/수정 API에서만 조회 및 수정할 수 있습니다.
- 관리자 인증 없이 비고 데이터에 접근할 수 없어야 합니다.

## 3.3 회원등급 변경

게스트가 추후 정회원으로 변경될 수 있습니다.

현재 회원정보에는 현재 등급을 저장합니다.

과거 출석 기록에는 출석 당시 회원등급을 별도로 저장하여 과거 데이터가 변경되지 않도록 합니다.

# 4. 분기별 팀 편성

각 분기마다 고정된 정회원 팀 편성이 존재합니다.

예:

2026년 3분기

블랙

- 김철수
- 이영희
- 박민수

화이트

- 홍길동
- 김영수
- 이민재

컬러

- 박철수
- 최영호
- 정민수

분기별 고정 팀 편성 대상은 정회원입니다.

게스트는 분기 고정 팀 편성 대상이 아닙니다.

분기가 바뀌면 기존 회원 목록은 그대로 사용할 수 있지만 팀 편성은 새롭게 진행합니다.

# 5. 기본 소속팀과 실제 출전팀

회원의 분기 고정팀과 특정 날짜의 실제 출전팀은 별개의 정보입니다.

예:

김철수

2026년 3분기 기본팀

- 블랙

실제 출전 기록

- 7월 1일: 블랙
- 7월 8일: 블랙
- 7월 15일: 컬러
- 7월 22일: 블랙

따라서 시스템에서는 다음 두 정보를 구분하여 저장합니다.

분기 기본팀

- LeagueMember에 저장

날짜별 실제 출전팀

- Attendance에 저장

# 6. 경기일

출석은 경기별이 아니라 날짜별입니다.

따라서 실제 농구를 진행한 날짜를 하나의 `GameDay`로 관리합니다.

예:

2026년 9월 2일

- 1경기
- 2경기
- 3경기
- 해당 날짜 출석 명단

동일 날짜에 여러 경기를 진행하더라도 회원 출석은 하루 1회만 기록됩니다.

# 7. 경기 대진

관리자가 경기일을 생성하면 기본 대진을 앱이 자동 생성합니다.

현재처럼 3팀이 존재한다면 기본적으로 모든 팀의 조합을 생성합니다.

예:

- 블랙 vs 컬러
- 블랙 vs 화이트
- 화이트 vs 컬러

자동 생성된 대진은 관리자가 다음 작업을 할 수 있어야 합니다.

- 경기 순서 변경
- 팀 변경
- 경기 추가
- 경기 삭제

즉 자동 생성은 편의를 위한 기능이며 실제 대진은 관리자가 최종 결정합니다.

팀 수를 3개로 하드코딩하지 않고 향후 팀 수 변경이 가능하도록 설계합니다.

# 8. 경기 결과

경기에는 최소 다음 정보가 필요합니다.

- 경기일
- 해당 날짜 경기 순서
- 팀 A
- 팀 B
- 팀 A 점수
- 팀 B 점수
- 경기 결과 유형
- 승리팀
- 비고

경기 결과 유형은 다음 세 가지를 기본으로 합니다.

- NORMAL: 정상 경기
- TIEBREAK: 동점 후 별도 승부결정
- FORFEIT: 몰수 경기

## 8.1 정상 경기

예:

블랙 42 : 38 컬러

결과 유형

- NORMAL

승리팀

- 블랙

## 8.2 동점 후 승부결정

정규 점수가 동점이어도 실제 승자가 존재할 수 있습니다.

예:

블랙 40 : 40 컬러

결과 유형

- TIEBREAK

승리팀

- 컬러

비고

- 자유투 승부

따라서 승리팀은 단순히 점수만으로 계산하지 않고 별도 필드로 관리합니다.

## 8.3 몰수 경기

몰수 여부를 시스템이 자동으로 판단하지 않습니다.

관리자가 직접 몰수 경기로 지정합니다.

예:

블랙 0 : 0 화이트

결과 유형

- FORFEIT

승리팀

- 블랙

몰수 기준 자체는 앱에서 자동화하지 않습니다.

운영진이 판단 후 경기 결과만 입력합니다.

# 9. 팀 순위

팀 순위는 관리자에게 직접 입력받지 않습니다.

모든 순위 정보는 경기 결과에서 자동 계산합니다.

계산 항목:

- 경기수
- 승
- 패
- 승률
- 득점
- 실점
- 득실차
- 상대전적
- 현재 연승 기록

## 9.1 순위 결정 기준

동률 발생 시 다음 순서로 순위를 결정합니다.

1. 승률
2. 승수
3. 득실차
4. 득점
5. 상대전적

## 9.2 연승 기록

팀의 최근 경기 결과를 시간순으로 계산하여 현재 연승 기록을 표시합니다.

예:

- 2연승
- 4연승
- 6연승

경기 결과가 수정되면 연승 기록도 자동 재계산합니다.

연승 횟수 자체를 DB에 별도 저장하지 않는 것을 원칙으로 합니다.

# 10. 출석

출석은 회원 + 경기일 기준으로 하루 1건만 존재합니다.

Attendance에는 다음 정보를 저장합니다.

- 경기일
- 회원
- 실제 출전팀
- 출석 당시 회원등급

출석한 사람만 Attendance 행을 생성하는 방식을 기본으로 합니다.

미출석자의 별도 결석 데이터는 생성하지 않습니다.

## 10.1 출석 등록

관리자 출석 화면에서는 회원 목록을 한 화면에 표시합니다.

예:

김철수
출석 ✓
실제 출전팀: 블랙

홍길동
출석 ✓
실제 출전팀: 컬러

이영희
미출석

정회원의 경우 해당 분기의 고정팀을 실제 출전팀 기본값으로 자동 설정합니다.

다른 팀에서 뛰었다면 관리자가 팀만 변경합니다.

게스트 역시 출석 시 실제 출전팀을 지정합니다.

# 11. 출석률

정회원과 게스트의 출석률 계산 기준은 동일합니다.

가입 시점, 정회원 여부 등을 별도로 고려하지 않습니다.

## 11.1 분기별 출석률

분기 출석률:

회원의 해당 분기 참석일수 ÷ 해당 분기의 전체 경기일수 × 100

여기서 전체 경기일수는 `GameDay 개수`를 의미합니다.

분기별 출석률은 `Attendance`와 해당 기간의 `GameDay` 원본 데이터를 기준으로 계산하며, 계산 결과를 별도 저장하지 않습니다.

예:

2026년 3분기 경기일

- 총 10일

김철수

- 8일 참석

출석률

- 8 / 10 = 80%

## 11.2 전체 누적 출석률

전체 누적 출석률:

전체 분기의 회원 참석일수 합계 ÷ 전체 분기의 경기일수 합계 × 100

분기별 출석률의 평균값을 사용하지 않습니다.

전체 출석률은 전체 기간의 `Attendance` 참석일 수 합계를 전체 기간의 `GameDay` 수 합계로 계산합니다. 정회원과 게스트 모두 같은 공식을 적용합니다.

예:

2026년 2분기

- 10 / 12

2026년 3분기

- 8 / 10

2026년 4분기

- 9 / 11

전체

- 27 / 33
- 81.8%

# 12. 공개 화면

일반 사용자는 별도 로그인이 필요하지 않습니다.

누구나 조회 기능을 사용할 수 있습니다.

## 12.1 홈

홈 화면에서 가장 중요한 리그 정보를 바로 확인합니다.

표시 정보:

- 현재 분기
- 팀 순위
- 승/패
- 승률
- 득실차
- 현재 연승 기록
- 최근 경기
- 분기 정회원 팀 편성 바로가기

## 12.2 경기

해당 분기의 경기 결과를 날짜별로 표시합니다.

예:

9월 2일

1경기
블랙 38 : 40 컬러
컬러 승

2경기
블랙 0 : 0 화이트
블랙 승
몰수 경기

## 12.3 출석

출석 화면에는 두 가지 조회 방식을 제공합니다.

날짜별

- 해당 날짜 출석자
- 당시 회원등급
- 실제 출전팀

회원별

- 참석 횟수
- 전체 경기일수
- 출석률

## 12.4 회원정보 접근 제한

회원정보 목록, 회원 상세정보, 회원정보 관리 화면은 관리자 전용입니다. 비로그인 일반 사용자는 이를 조회할 수 없습니다.

다만 팀 편성, 출석, 우승팀 멤버 등 공개 기능에 필요한 회원 이름은 표시할 수 있습니다.

관리자 전용 `비고`는 일반 회원 목록과 일반 회원 상세 화면에 표시하지 않습니다.

## 12.5 회원 상세

회원 상세 화면은 관리자 전용입니다. 관리자가 회원 한 명을 선택하면 다음 정보를 확인합니다.

- 태어난 년도
- 키
- 포지션
- 현재 회원등급
- 전체 누적 출석률
- 분기별 출석률
- 분기별 고정 소속팀
- 날짜별 실제 출전팀 기록

관리자 전용 `비고`는 표시하지 않습니다.

향후 개인 경기 스탯 기능이 추가될 경우 이 화면을 확장합니다.

## 12.6 분기별 팀 편성

선택한 분기의 고정 정회원 팀 편성을 확인합니다.

예:

2026년 3분기

블랙

- 김철수
- 이영희

화이트

- 박철수
- 최영수

컬러

- 홍길동
- 김민수

팀 상세에서는 해당 팀의 성적과 정회원 명단을 함께 볼 수 있도록 합니다.

## 12.7 과거 리그 조회

화면 상단에서 분기를 선택할 수 있습니다.

예:

- 2026년 4분기
- 2026년 3분기
- 2026년 2분기

분기를 변경하면 다음 화면들이 선택한 분기를 기준으로 변경됩니다.

- 순위
- 경기
- 출석
- 팀 편성
- 최종 우승팀
- 해당 리그 당시 우승팀 멤버

# 13. 관리자 인증

회원 로그인 기능은 구현하지 않습니다.

관리자만 별도의 관리자 로그인 기능을 사용합니다.

로그인 입력값:

- 관리자 아이디
- 관리자 비밀번호

회원 DB와 관리자 인증은 분리합니다.

초기 버전에서는 관리자 계정 관리 테이블을 만들지 않고 단일 관리자 계정을 사용합니다.

관리자 정보는 서버 환경변수 등을 이용해 관리합니다.

비밀번호를 소스코드나 Git 저장소에 평문으로 기록하지 않습니다.

서버에는 비밀번호 해시값을 저장합니다.

관리자 인증 성공 후 관리자 API 사용이 가능해야 합니다.

화면만 숨기는 방식이 아니라 서버의 관리자 API 자체에서도 인증을 검사합니다.

초기 버전에서는 로그인 성공 후 HttpOnly Cookie 기반 관리자 인증 방식을 기본 방향으로 합니다.

따라서 다음 원칙을 적용합니다.

- 모바일 우선
- 순위를 앱 실행 후 빠르게 확인
- 출석을 한 화면에서 일괄 입력
- 정회원의 기본팀 자동 선택
- 실제 다른 팀 출전 시 쉽게 변경
- 경기 결과를 한 화면에서 빠르게 입력
- 순위는 경기 저장 후 자동 반영
- 관리자 작업의 터치 횟수를 최소화
- 관리자 회원정보를 한 화면에서 쉽게 조회/수정
- 관리자 비고는 일반 사용자에게 노출하지 않음
- 과도한 기능을 초기 버전에 넣지 않음

# 24. 현재 확정된 핵심 원칙 요약

1. 리그는 분기 단위입니다.
2. 분기마다 정회원 팀 편성을 새로 합니다.
3. 과거 분기 데이터는 유지합니다.
4. 정회원과 게스트가 존재합니다.
5. 게스트는 고정 분기팀 편성 대상이 아닙니다.
6. 회원정보에는 태어난 년도, 키, 포지션을 저장합니다.
7. 포지션은 2개 이상 입력할 수 있습니다.
8. 회원별 관리자 전용 비고를 저장할 수 있습니다.
9. 관리자 비고는 일반 사용자 화면과 공개 API에 노출하지 않습니다.
10. 출석은 날짜 기준 하루 1회입니다.
11. 출석 시 실제로 뛴 팀을 기록합니다.
12. 분기 기본팀과 실제 출전팀은 별도로 관리합니다.
13. 정회원/게스트 모두 동일한 방식으로 출석률을 계산합니다.
14. 출석률의 분모는 해당 분기의 전체 경기일수입니다.
15. 경기일 생성 시 기본 대진을 자동 생성합니다.
16. 관리자가 대진을 수정할 수 있습니다.
17. 몰수 여부는 관리자가 직접 지정합니다.
18. 몰수 경기를 시스템이 자동 판정하지 않습니다.
19. 동점 경기는 별도의 승리팀 지정이 가능합니다.
20. 순위는 경기 결과를 기준으로 자동 계산합니다.
21. 순위 기준은 승률 → 승수 → 득실차 → 득점 → 상대전적입니다.
22. 팀별 현재 연승 횟수를 자동 계산합니다.
23. 일반 사용자는 로그인 없이 조회합니다.
24. 관리자만 ID/PW 인증 후 데이터를 관리합니다.
25. 관리자 계정과 회원 계정은 별개입니다.
26. 관리자 페이지에는 회원정보 탭을 제공합니다.
27. 관리자 회원정보 화면에서는 회원 기본정보와 관리자 비고를 조회/수정할 수 있습니다.
28. 완료 경기에서 참가팀 선수의 개인 득점을 관리합니다.
29. 개인 득점 순위와 득점 외 개인 스탯은 향후 확장 범위입니다.

# 25. v1.0 개발 원칙

## 추가 확정 요구사항: 필승조합

- 홈 승리기여도 바로 아래에는 팀별 1위 미리보기와 전체보기 링크를 표시합니다. `/leagues/:id/winning-combinations` 상세페이지는 팀 탭과 팀 전체 경기 수/승/패/평균 승률, 팀별 TOP7을 제공합니다. 유효 조합이 없는 팀도 빈 상태로 표시합니다.
- 공통 계산 결과를 teams 배열로 반환하고 각 팀 내부에서 별도로 순위를 정합니다. 공개 API는 팀당 최대 7개, 관리자 인증 API는 팀당 최대 20개입니다. 관리자 리그 관리에서도 팀 탭으로 조회합니다.
- 승리팀은 유효한 DB 승리팀을 우선하고, NORMAL(과거 result_type NULL 포함)의 완료 경기에서 점수가 유효하고 서로 다르면 점수로 보완합니다. FORFEIT은 필승조합에서 제외하며 승자를 결정할 수 없는 경기 역시 제외합니다. 팀 평균과 조합에 같은 경기 조건을 적용합니다.
- 관리자 단건 생성/수정은 NORMAL 완료 경기의 승리팀을 점수로 계산해 result_type과 함께 저장합니다. 명시적 승자가 필요한 동점/TIEBREAK/FORFEIT의 기존 검증과 예정 전환 시 결과 초기화는 유지합니다.
- PRESENT 출석의 actual_team_id로 날짜별 실제 참가자를 구성하고 그 날짜 해당 팀의 각 경기에 반영합니다. 활성 회원만 포함하며 정회원/게스트를 모두 포함합니다.
- league_member.id 오름차순과 실제 팀 ID로 조합을 식별합니다. 3명부터 실제 참가자 전원까지 모든 조합을 생성하며, 함께 출전 3경기 이상만 순위에 포함합니다.
- 필승지수(winImpact) = 조합 승률 - 해당 팀의 리그 전체 정상 완료 경기 승률입니다. 조합 미출전 경기 승률은 사용하지 않으며 음수도 포함합니다.
- 팀 내부에서 반올림 전 필승지수 → 조합 승률 → 승수 → 경기 수 내림차순, 인원 수 → canonical member key 오름차순으로 정렬합니다. 소수점 한 자리로 표시하며 필승지수 단위는 %p입니다. 포함관계 조합도 그대로 유지합니다.
- DB 구조 변경 없이 계산합니다. 관리자 전용 회원정보를 공개하지 않고, 홈 로딩/오류는 필승조합 영역에서 독립 처리합니다.
- 기존 통계 디자인과 간격을 재사용하고 390px 모바일에서 이름 줄바꿈과 숫자 표시를 보장합니다.

본 문서는 어른이농구 리그별 스코어 APP v1.0의 개발 기준 문서입니다.

Codex를 포함한 개발 도구는 본 문서의 요구사항을 기준으로 구현합니다.

다음 원칙을 준수합니다.

1. 본 문서에 없는 기능을 임의로 추가하지 않습니다.
2. 확정된 비즈니스 규칙을 임의로 변경하지 않습니다.
3. 기능 요구사항과 기술 구현이 충돌하는 경우 기능 요구사항을 우선합니다.
4. DB 구조 변경이 필요한 경우 기존 데이터 보존을 고려합니다.
5. 관리자 전용 데이터가 공개 API에 노출되지 않도록 합니다.
6. 회원의 관리자 비고(note)는 관리자 인증 API를 통해서만 접근할 수 있도록 합니다.
7. 순위, 승률, 득실차, 연승, 출석률 등 계산 가능한 값은 원칙적으로 중복 저장하지 않습니다.
8. 모바일 사용성을 우선합니다.
9. 초기 v1.0 범위를 넘어서는 과도한 기능을 구현하지 않습니다.
10. 향후 확장성을 고려하되 현재 필요하지 않은 복잡한 구조를 미리 만들지 않습니다.

개발 과정에서 본 문서와 다른 새로운 요구사항이 확정되면 문서를 먼저 수정한 후 구현합니다.
